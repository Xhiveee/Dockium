# Dockium

Панель управления экземплярами через Docker: веб-интерфейс, живая консоль,
файловый менеджер, образы и несколько Docker-хостов под управлением агентов.

Dockium состоит из двух самостоятельных сервисов:

- **web** — панель: React-интерфейс, Connect-RPC API, SQLite, приём gRPC-соединений агентов.
- **agent** — агент на Docker-хосте: сам подключается к панели по gRPC и выполняет
  команды Docker CLI. Бизнес-данные не хранит.

## Возможности

- Экземпляры (Docker-контейнеры): создание, запуск, остановка, перезапуск,
  принудительная остановка, автоматический старт при подключении агента,
  авторестарт при аварийном завершении.
- Живой статус, метрики CPU/памяти/сети контейнеров и агентов, переподключение
  без перезагрузки страницы.
- Консоль: поток `docker logs` с кодировками UTF-8/Windows-1251/CP866/KOI8-R и
  отправка команд в stdin контейнера (работает и для TTY-контейнеров).
- Файловый менеджер: список, чтение и редактирование, загрузка, скачивание,
  создание, переименование, удаление, права доступа, ZIP-архивы. Файлы
  ограничены каталогом данных экземпляра на агенте.
- Образы: список, загрузка из реестра, сборка из Dockerfile с потоковым выводом,
  удаление, `docker inspect`; список контейнеров агента.
- Расписания: запуск/остановка/перезапуск/команда по интервалу или ежедневно.
- Пользователи и роли, доступ к экземплярам (управление/консоль/файлы).
- Безопасность: bcrypt, серверные сессии в HttpOnly cookie, хэши токенов агентов,
  журнал входов, автоматические и ручные блокировки IP, журнал API, список
  активных сессий с отзывом.
- Тёмный мягкий интерфейс, адаптивная вёрстка, единые Toast-уведомления.

## Архитектура

```
браузер ──Connect-RPC (HTTP)──► web ──SQLite (WAL)
                                  │
                                  │ gRPC bidi stream (агент подключается сам)
                                  ▼
                             agent ──Docker CLI──► dockerd
                                  │
                                  └── каталог данных экземпляров
```

- Панель отдаёт собранный SPA и API на одном origin.
- Агент сам устанавливает исходящее соединение к панели и поддерживает его
  keepalive/переподключением; панель при подключении отправляет полный `Sync`
  экземпляров и актуализирует состояние.
- Консоль, вывод сборки и скачивание файлов мультиплексируются по одному
  соединению с агентом через stream-id.

## Требования

- Go 1.27+;
- Node.js 24+ и npm (для разработки интерфейса);
- Docker 24+ на машинах агентов;
- Linux-сервер с Docker для `install.sh` (или запуск бинарников вручную).

## Разработка

Запустите панель (backend + API):

```sh
cd src
go run ./cmd/dockium-web \
  -addr 127.0.0.1:3434 \
  -agent-addr 127.0.0.1:3443 \
  -data-dir ./data \
  -web-dir ./web/dist
```

Запустите интерфейс с hot-reload (Vite проксирует API на `127.0.0.1:3434`):

```sh
cd src/web
npm install
npm run dev
```

Откройте <http://127.0.0.1:5173>, создайте администратора, затем агента.

Соберите и запустите агент (токен показывается один раз при создании агента):

```sh
cd src
go run ./cmd/dockium-agent \
  -panel http://127.0.0.1:3443 \
  -token '<TOKEN>' \
  -data-dir ./data/agent
```

Для TLS-подключения агента используйте `https://` в `-panel` и при
необходимости `-ca`, `-skip-verify` (только для тестов) или `-server-name`.

### Сборка

```sh
cd src/web && npm run build     # интерфейс в src/web/dist
cd src && go build ./cmd/dockium-web ./cmd/dockium-agent
```

Для production веб-сервер должен получить `-web-dir` на собранный `dist`.

### Тесты

```sh
cd src && go test ./... && go vet ./...
cd src/web && npm run typecheck && npm test
```

## Развёртывание на сервере

```sh
sudo DOCKIUM_AGENT_TOKEN='<токен агента>' ./install.sh
```

Скрипт собирает образы `dockium-web` и `dockium-agent`, создаёт каталог
`/opt/dockium`, генерирует `docker-compose.yml` и запускает панель (порты
`3434` и `3443`). Если токен не указан, поднимается только панель — агента
можно добавить позже, создав его токен в интерфейсе.

Переменные установки:

| Переменная | Значение |
|---|---|
| `DOCKIUM_AGENT_TOKEN` | токен агента, включает запуск агента в compose |
| `DOCKIUM_AGENT_ENDPOINT` | адрес панели для агентов, который увидит пользователь (например `panel.example.com:3443`) |
| `DOCKIUM_TRUST_PROXY` | `1`, если панель стоит за доверенным reverse proxy |
| `DOCKIUM_SECURE_COOKIES` | `1` для cookies только через TLS |
| `DOCKIUM_DIR` | каталог установки, по умолчанию `/opt/dockium` |
| `TZ` | часовой пояс панели (влияет на расписания) |

Для публичного доступа поставьте панель за TLS reverse proxy (Caddy/Nginx) и
включите `DOCKIUM_SECURE_COOKIES=1`. Агентский gRPC-порт `3443` также следует
закрыть TLS или приватной сетью.

## Порты

- `3434` — интерфейс и API панели (HTTP).
- `3443` — gRPC для агентов (HTTP/2, при необходимости TLS).

## Безопасность

- Пароли — bcrypt (cost 12), сессии хранятся в SQLite хэшами.
- Cookie сессии: `HttpOnly`, `SameSite=Strict`, при TLS — `Secure`.
- Запросы с изменением проверяются по `Origin`; CORS не открыт.
- Токены агентов хранятся только в виде SHA-256 хэшей, показываются один раз.
- Пять неудачных входов за 10 минут блокируют IP на час; блокировки можно
  добавлять и снимать вручную.
- Файловый API принимает только идентификатор экземпляра и работает в его
  каталоге данных; выход за пределы каталога и symlink-побег отклоняются.
- Агент имеет доступ к Docker-сокету и поэтому является привилегированным
  компонентом: запускайте его только на доверенных хостах.

## Ограничения MVP

- Сборка образа из Dockerfile выполняется без файлов контекста (только Dockerfile).
- Максимальный размер загрузки файла по умолчанию — 1024 МБ; администратор
  может изменить лимит в настройках панели в диапазоне 1–4096 МБ. Редактирование
  файлов — 4 МБ, скачивание — 256 МБ.
- Расписания используют часовой пояс панели.
- Консоль читает `docker logs`; интерактивный stdin работает через Docker API
  attach и требует открытого stdin (`-i`) у контейнера — Dockium добавляет его
  автоматически.
